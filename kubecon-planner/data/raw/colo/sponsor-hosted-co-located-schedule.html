Stateful Done Right Hosted by Cockroach Labs | SOLD OUT
Off-Site Location
Sponsor-hosted Co-located Events
12:00 PM – 4:00 PM

Please note that this is an off-site Sponsor-hosted Co-located event.

Location: Le Méridien Salt Lake City Downtown, 131 S 300 W, Salt Lake City, UT 84101

On Kubernetes, pets get names and a human on call at 3 a.m. — cattle get managed by the herd. Your database should be cattle. Join our Day 0 workshop at KubeCon 2026 and get hands-on with stateful workloads done right: go from "why are databases on K8s so hard?" to running a production-grade, self-healing CockroachDB cluster with the GA CockroachDB Kubernetes Operator. Because CockroachDB is symmetric — every node is equal, with no primary to fail over — the Operator manages each node as a CrdbNode custom resource, not a StatefulSet, so any node can be replaced, rescheduled, or lost without ceremony. You'll deploy, scale, break, and recover a distributed SQL cluster live — and watch it heal itself. Designed for platform engineers and SREs who run stateful workloads on Kubernetes.

Instructors: Felipe Gutierrez and Nathan Zamecnik

Discovering and Securing AI Agents in Kubernetes Hosted by Tigera | SEPARATE REGISTRATION REQUIRED
Off-Site Location
Sponsor-hosted Co-located Events
2:00 PM – 5:00 PM

Please note that this is an off-site Sponsor-hosted Co-located event.

Location: Le Méridien Salt Lake City Downtown, Address: 131 S 300 W, Salt Lake City, UT 84101| Room: Triumph Salon I

Governing autonomous AI agents is no longer a design problem — it’s an operational one. Agents are running in production clusters today, calling tools over MCP, invoking each other, and reaching external model providers.

This session is built entirely on what we’ve seen in real environments – both in Kubernetes and beyond. Tigera CTO Peter Kelly walk the path we’ve watched every team take, in order. Discovery first, because agents arrive through application teams rather than platform teams. Through to registration with identity, because a Kubernetes service account tells you which pod made a call but nothing about which agent, acting for whom, with what authority. Then governance – expressing intent as policy at the level of tools and data rather than IPs and ports, and running it in observation mode long enough to trust it before anything gets enforced.

It’s architecture-first and deliberately vendor-neutral: the goal is a mental model you can apply to whatever you’re building on.
