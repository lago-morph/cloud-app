# Decision drafts — B-10 (SEC, local)

### DEC-PENDING-B-10-1 — Framework-internal secret names; the reserved prefix is a plain `framework` prefix
Origin: ai-proposed · Status: accepted · Affects: SEC-REQ-001, SEC-REQ-003, secrets.md §2, DEC-0064, B-11, B-12, B-13, B-16, D-01, D-02, D-03

`src/secrets/names.ts` defines `FRAMEWORK_SECRETS`: `frameworkSessionKey` (AUTH), `frameworkGoogleClientSecret` (GOOGLE; the name B-13 already reads, DEC-PENDING-B-13-2, so no mismatch), `frameworkR2AccessKeyId` and `frameworkR2SecretAccessKey` (FILES' R2 token as S3 credentials, created by provisioning), and `frameworkLocalTicketKey` (FILES' local transfer route; local only). Locations follow SEC-REQ-003 through CFG's `secretLocation` (e.g. `SECRET_FRAMEWORK_SESSION_KEY`). A name is reserved when it starts with `framework` (simplest reading of "reserved prefix"; `frameworks` is reserved too). `checkSecretDeclarations(names)` is the build's check of the app's declared names (lowerCamelCase `^[a-z][a-zA-Z0-9]*$` like CFG keys, no duplicates, not reserved), failing with `CORE.MISCONFIGURED` listing every problem (as DEC-PENDING-B-09-2); B-16 calls it. At runtime a reserved name is `SEC.UNDECLARED` for the app even if declared, so the check is not the only guard.

### DEC-PENDING-B-10-2 — Runtime service shape: one per request over a reader; empty is missing; store errors are not echoed
Origin: ai-proposed · Status: accepted · Affects: SEC-REQ-001, SEC-REQ-002, SEC-REQ-005, LOG-REQ-005, B-12, B-13, B-16, D-01

`createSecretsService({ declared, read, log })` (`src/secrets/service.ts`) is the app's `Services.secrets`; the runtime's `createServices` makes one per request, so the value reuse inside it is per request only (SEC-REQ-005). `read(name)` is the target's store; `envSecretReader(env, target)` reads `SECRET_<NAME>` from the Worker env for local and Cloudflare (D-01 can use it unchanged). An absent, empty, or non-string value is `SEC.MISSING` (an empty `.dev.vars` assignment or Worker secret is not a usable value); misses are not remembered, so a later read in the same request may see a value. A non-`FrameworkError` from the reader becomes `SEC.UNAVAILABLE` with a message naming only the secret, logged once with `logFailure` (DEC-PENDING-B-04-2) when a log is given; the reader's own error is not attached, so nothing it holds reaches logs or responses. No time budget is applied: there is no SEC parameter, and the local and Cloudflare readers are synchronous env lookups. Framework code uses `createFrameworkSecrets({ read, log })`, which accepts only `FRAMEWORK_SECRETS` names (AUTH's and GOOGLE's `getSecret` can be built on it).

### DEC-PENDING-B-10-3 — `secrets set` argument rules and stdin handling (SEC-AC-004 logic)
Origin: ai-proposed · Status: accepted · Affects: SEC-REQ-004, SEC-AC-004, CLI-REQ-004, B-17

`src/secrets/set-command.ts`: `parseSecretsSetArgs(args after "secrets set")` accepts exactly one positional (the name) and `--target`/`--stage` (space or `=` form, once each, target `local` or `cloudflare`). A second positional, `--value`, or any unknown option is refused with `SecretsSetUsageError`; no message repeats any argument (a value typed by mistake is never printed, CLI-REQ-004). `readSecretValue(stdin)` decodes UTF-8 across chunks and removes one trailing `\n` or `\r\n` (what `echo` adds); empty input is refused. `checkSettableName(name, declared)` accepts a declared app secret or any framework-internal name (the owner sets `frameworkGoogleClientSecret` this way; replacing the session key is allowed) and lists the settable names without repeating the input. The CLI (B-17) composes parse → load app → check name → read stdin → `setLocalSecret` for `--target local`; the stage is accepted but unused locally (one `.dev.vars`, as DEC-PENDING-B-09-1 for config).

### DEC-PENDING-B-10-4 — `.dev.vars` writing matches how Wrangler reads it
Origin: ai-proposed · Status: accepted · Affects: SEC-REQ-003, SEC-AC-003, secrets.md §2 Local, B-17

Wrangler 4.149.0 (PAR-101) loads `.dev.vars` with its bundled dotenv 16.3.1 `parse` and then dotenv-expand 12.0.2 `expand` (`node_modules/wrangler/wrangler-dist/cli.js`, `loadDotEnv`), so `$NAME` in a value would be substituted. `src/secrets/dev-vars.ts` transcribes those read rules (`readDevVars`), escapes every `$` as `\$`, and writes the value with the first quoting (`'`, `"`, `` ` ``) whose line reads back exactly; a value with a line break, or one no quoting represents (e.g. containing all three quotes and a `#`), is refused with a message naming only the location. Setting a name replaces its first assignment in place (also a multi-line quoted one), removes duplicates, keeps every other line, and normalises line endings to `\n`. `src/secrets/local.ts`: `setLocalSecret(appDir, name, value)` is local `setSecret`; `ensureDevSecrets(appDir)` (called by `dev`) adds `frameworkSessionKey` and `frameworkLocalTicketKey` when absent or empty, each 32 random bytes (PAR-253) in base64url, never changing an existing value, and returns the names generated. The file is written with mode `0600`. The unit tests check the written text with an independent transcription of Wrangler's read rules; the real Wrangler round trip is covered by B-T1's integration suite (`test/integration/secrets/cli.test.ts`).
