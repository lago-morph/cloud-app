# Decision drafts — D-04

## Interface for D-03 (published early; final form below in DEC-PENDING-D-04-1)

`packages/framework/src/provision/cloudflare/d1/operations.ts`:

```ts
import type { CloudflareApi } from "../account.js";
import type { ListedDatabase, TargetOperations } from "../../core/operations.js";

export interface D1Options {
  readonly api: CloudflareApi;          // D-03's real client (auth/proxy per DEC-0107); may throw on network errors/timeouts
  readonly accountId: string;
  readonly limits?: Partial<CopyLimits>; // tests only; defaults PAR-216/PAR-217/PAR-218
}
export type D1DatabaseOperations =
  Pick<TargetOperations, "createDatabase" | "copyDatabase" | "dropDatabase" | "migrationDatabase" | "checkMigratedDatabase">
  & { listDatabases(): Promise<ListedDatabase[]> };   // every D1 database of the account (paged), for listStageResources
export function d1DatabaseOperations(options: D1Options): D1DatabaseOperations;
```

D-03 builds its `TargetOperations` as `{ ...d1DatabaseOperations({ api, accountId }), target: "cloudflare", dialect: "sqlite", … }`
and uses `listDatabases()` for `StageResources.databases`. A `StageDatabase.id` is the D1 UUID; that is also
what the Worker's D1 binding needs (`database_id`).

`CloudflareApi` responses this module relies on: `{ status, body }` with `body` the parsed JSON object, or
anything else (string, `undefined`) for a non-JSON answer; a thrown error for no answer.

Parameter changes: none.
