## Draft entries

1. **The first publish of each package is by hand; every later one is trusted publishing.** `npm trust` states "The package you're configuring must already exist on the npm registry" [S2]; the trusted-publisher page configures from "your package settings" [S1]. So no workflow can make the first publish without a token. Chosen: the owner publishes 0.1.0 of both packages once from a clean checkout (`npm login`, no stored token), then configures the trusted publisher; `release.yml` skips a version already on npm, so tagging `v0.1.0` afterwards still creates the GitHub release, and a re-run after a failed later step is safe. Cost: 0.1.0 carries no provenance. Rejected: a stored `NPM_TOKEN` secret for the first release (a long-lived credential the owner chose to avoid); a placeholder version to reserve the names (an extra, misleading version on npm that must then be deprecated).
2. **Trusted publishing requirements met in `release.yml`** [S1]: GitHub-hosted runner (`ubuntu-24.04`); `id-token: write` only on the publish job; npm CLI 11.5.1 or later (Node 22.22.0 ships npm 10.9, so the job installs `npm@11.21.0`); Node 22.14.0 or later (22.22.0, the engines pin). The trusted publisher's allowed actions must include **npm publish**: only `npm stage publish` is always allowed, and a staged publish waits for a maintainer's 2FA approval [S1]. A new trusted-publisher configuration must publish within 2 days or it expires [S1] (stated in RELEASING.md). Workflow filename recorded: `release.yml`; no GitHub environment.
3. **Provenance**: `npm publish --provenance --access public` in CI [S3]. Trusted publishing from GitHub Actions also generates provenance by default for a public repository and package [S1]; the flag keeps it explicit. `package.json` `repository.url` is `git+https://github.com/lago-morph/cloud-app.git`, with `directory`, matching the repository case-sensitively [S1][S3]. `publishConfig.provenance` is not set, because it would make the owner's local first publish fail.
4. **Scope and organization**: a scope is granted to the user or organization of that name [S5], and organization scopes need an npm organization [S5]. The owner's npm user name is `lago-morph` (confirmed 2026-10-26), so the scope `@lago-morph` is the owner's user scope and no organization is needed. Scoped packages are private by default, so both packages set `publishConfig.access: "public"` and the workflow passes `--access public` [S5][S3].
5. **Starter name**: `npm init @usr/foo` runs `npm exec @usr/create-foo` [S4]. The package is `@lago-morph/create-prototype-app`, run as `npm create @lago-morph/prototype-app <dir>`; it lives in the same scope, so one organization covers both packages. Its one bin is `create-prototype-app`. It has no runtime dependencies (Node built-ins only).
6. **Starter behaviour**: copies the template (bundled at `prepack` from `apps/template`, with `.gitignore` stored as `gitignore`, because npm never packs `.gitignore`; restored on copy), leaving out the template's ignored paths; sets `package.json` `name` from the folder, and the app name (PAR-290: 1–20 lowercase letters and digits) in `src/app.ts` and `index.html`; pins `@lago-morph/prototype-framework` at the starter's own version (released in lockstep; `--framework <spec>` overrides, used by the tests); copies the skill (without `skill/scripts/`) into `.claude/skills/prototype-framework/`, where Claude Code loads project skills, and prints the plugin commands as the alternative (`--no-skill` skips the copy); runs `npm install` (`--no-install` skips). Refuses a non-empty folder unless `--force`, like `skill/scripts/scaffold` (SKILL-AC-005), which stays for in-repository use with an unreleased framework. `postpack` removes the bundle again so a checkout's bin reads `apps/template` directly.
7. **One version for everything**: the framework, the starter, the template's pin and `plugin.json` are released together at one version (`scripts/release-check.mjs` and its unit test enforce it on the tag; a unit test and a skill test check the repository agrees). **0.1.0** is kept for the first release: it is already the framework's version and the template's exact pin, and a 0.x version says the API may still change (release 1 has unverified Cloudflare steps and AWS deferred). 1.0.0 should wait for a release whose cloud steps are verified.
8. **Plugin layout**: marketplace `lago-morph` at `.claude-plugin/marketplace.json` (required `name`, `owner.name`, `plugins` [S7]); one entry `prototype-framework` with relative source `./skill` (must start with `./`, no `..` [S7]). The plugin root is `skill/` itself, with `skill/.claude-plugin/plugin.json` (`name` kebab-case and equal to the entry name [S6][S8]); with `SKILL.md` at the plugin root, no `skills/` and no `skills` key, the plugin "loads as a single skill" [S8], so the skill is not moved and its tests and links are unchanged. `version` is set only in `plugin.json` (it wins over the entry's [S7]). Install id: `prototype-framework@lago-morph`. Checked with `claude plugin validate .` and `claude plugin validate ./skill --strict` (Claude Code 2.1.310: passed) and a local `claude plugin marketplace add ./` + `install` + `details` (one skill, `prototype-framework`) in a scratch config directory. `/plugin marketplace add lago-morph/cloud-app` reads the default branch, so the plugin is live once this work is on `main`. `tests/skill/plugin-manifest.test.ts` checks the documented fields and rules, and runs `claude plugin validate` when the CLI is on PATH.
9. **CI** (`.github/workflows/ci.yml`; committed at `.github/workflows-to-install/` because this session's GitHub credentials lack the `workflow` scope, so the owner moves both files, RELEASING.md step 0; pull requests and pushes to `main`, `contents: read`, no secrets): `npm ci`, `npm run verify`, the skill tests, the offline starter test, and `npm pack --dry-run` of both packages. **Pins** (new, for the parameters register): `actions/checkout` v7.0.1 at `3d3c42e5aac5ba805825da76410c181273ba90b1`, `actions/setup-node` v7.1.0 at `949feb2413d6458794dcd2491c4babbbce0c15c1`, npm CLI `11.21.0` in the release job; runner `ubuntu-24.04`. Checked with actionlint 1.7.12 (the official binary; the npm `actionlint` package is a 2022 WebAssembly build); shellcheck was not installed, so the shell lint inside actionlint did not run.
10. **Offline starter test** (`packages/create-prototype-app/test/create.offline.test.ts`, integration layer and CI): packs the framework (`--ignore-scripts`, so it never rewrites `dist/` under suites running in parallel; the framework must be built first) and the starter, runs the packed starter into a temp folder against the framework tarball, installs with `npm ci --offline`, then `build` and `verify` the new app. `npm ci` caches package tarballs but not registry metadata, so an install without a lockfile cannot resolve ranges offline; the test cuts the app's lockfile from the repository's (`test/lockfile.ts`). Local run: passed in about 55 s.
11. **Framework package contents**: `files` adds `!dist/**/*.test-support.*` (test helpers for the framework's own unit tests); README.md and LICENSE added to the package folder. `prepack` stays `npm run build` without cleaning `dist/` first: `skill/scripts/scaffold` packs during the compliance run, and deleting `dist/` there would break suites running at the same time; the release job builds from a fresh checkout, so no stale files reach npm. A `clean` script is available.
12. **Skill text**: `reference/local-development.md` "Starting a new app" now leads with `npm create @lago-morph/prototype-app@latest my-app` (the plugin and the copied skill have no `skill/scripts/scaffold`), keeping the scaffolder for a checkout; `SKILL.md` names both. Budgets and link checks pass.
