## How to merge bottom-up

- Merge each stack from the bottom: the PR whose base is `main` first, then the one stacked on it.
- When a PR's base branch is merged and **deleted**, GitHub retargets the PR above it to the merged PR's base (normally `main`). So enable "Automatically delete head branches", or delete the merged branch by hand, before merging the next PR up.
- After a retarget, the upper PR's diff can show the lower PR's commits until it is updated: merge `main` into it (these branches are never rebased or force-pushed), push, and re-check CI before merging.
- A PR with a cross-stack merge precondition (progress §4, "after") is merged only after that PR is in `main`; merge `main` into it first.
- The lockfile is never hand-merged: on a conflict, take `main`'s `package-lock.json` and run `npm install` (plan.md §9.2).
- Record the PR number and final size here when a PR opens, and its merge in `progress-v0.2.0.md`.
