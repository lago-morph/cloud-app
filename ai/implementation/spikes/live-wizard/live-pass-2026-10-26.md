## Defects and notes

- **D1 (network step)**: packages/framework/src/provision/cloudflare/cloudflare-setup.ts:708
  reaches `https://<subdomain>.workers.dev/`, the bare account subdomain, which got no answer here
  while Worker hosts on the same subdomain did. Every real run therefore ends "cannot reach the
  account's workers.dev subdomain" and exits 1. Not fixed here; a likely fix is to reach a
  Worker's host on it (for example the mail sink's, `prototype-mailsink.<subdomain>.workers.dev`).
- **D2 (summary)**: cloudflare-setup.ts:587-591 and :651: a bootstrap run that applies no step
  but writes the record (here: the record's first `setupVersion`) does not set `changed`, so it
  prints "Everything is already set up and current: nothing to do."
- **D3 (driver artifact)**: the record written in 2b has `frameworkVersion: "unknown"`:
  `frameworkVersion()` (setup-record.ts:122-129) resolves `package.json` from the module's URL,
  which the esbuild-bundled driver does not have beside it, and `live-pass.ts` passed no
  `frameworkVersion`. A real CLI run records the package version. The record stays readable and
  current.
