# Test-change review — S3 (CI and release restructuring), 2026-10-31

Change set: the once-green tests that S3's PRs 15 and 17 move or change (plan-v0.2.0 §7a.1.9). Every test S3 adds is new: `tests/ci-classify.unit.test.ts` is not a once-green test and is not listed here.

## Groups

### G1 — `behaviour-changed`: the harness's Playwright project names (PR 15)
- **Reason:** plan-v0.2.0 §7a.2.4 and S3's PR 15 split the e2e project `e2e` into `e2e-api` and `e2e-ui`. DEC-0638 records the split.
- **Change:** `tests/compliance/harness/selection.unit.test.ts`, test "local selection is the driver's…". It now expects `--project integration --project e2e-api --project e2e-ui`, where it expected `--project integration --project e2e`. This applies to both the local and the cloud selection.
- **Unchanged:** the "variadic --project" test, which must still hold with three projects.
- **Coverage:** the same specs still run, each exactly once. `npx playwright test --list` shows 31 e2e tests in 15 files, split 14 (e2e-api) and 17 (e2e-ui), as under the single `e2e` project.

### G2 — `refactor-only`: layer moves, each test now collected once (PR 17)
- **Reason:** plan-v0.2.0 §7a.2.4 "No duplicates"; DEC-0640, which supersedes DEC-0405.
- **Changes:**
  - `tests/skill/example-copies.unit.test.ts` becomes `tests/skill/example-copies.test.ts`, as a rename-only commit. The integration layer only collects it. Its five checks are unchanged in every assertion. The header comment now describes the new layer.
  - `vitest.integration.config.ts` excludes `**/*.unit.test.ts`. The ten `tests/compliance/criteria/**/*.unit.test.ts` files no longer run a second time in the integration layer; they still run in the unit layer. Their code is unchanged.
- **Evidence:** `node scripts/ci/classify.mjs --check-duplicates`, which reports "No test file is collected by two layers" (unit 237, integration 116, Playwright integration 6, e2e-api 9, e2e-ui 6).
- **Note for the reviewer:** `criteria/compl/support.unit.test.ts` has a `[COMPL-AC-001]` describe. Its outcome no longer reaches the driver through the integration run, because the driver reads the unit layer only for UNIT_LEVEL IDs. COMPL-AC-001 is still evidenced by `criteria/compl/targets.test.ts`, which is integration.

### G3 — `behaviour-changed`: the SKILL-AC-004 wiring test follows the move (PR 17)
- **Reason:** DEC-0640.
- **Before:** `example-copies` "CI wiring: the framework's root verify runs this byte-for-byte check" asserted that root `verify` runs `test:unit`, that `test:unit` uses the unit config, and that the unit config includes `tests/**/*.unit.test.ts`.
- **After:** it asserts that root `verify` runs `vitest run --config vitest.integration.config.ts … tests/skill/example-copies.test.ts`, and that the integration config includes `tests/skill/**/*.test.ts`.
- **Assessment:** the same property (the root `verify` runs this check), restated for the new layer. Nothing is weaker: the old assertion would no longer be true of the file.
