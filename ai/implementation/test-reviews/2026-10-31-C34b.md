## Group: test-was-wrong — the fake setup world refused a Secrets Store read to a token holding Secrets Store Read
Cites: ai/implementation/root-causes/2026-10-31-C-34a-fake-secrets-store-read.md (review round 2: accepted; reviewer `session_014mWQ6jgCbDDUrS6CFmp5o3`)
Tests:
- `packages/framework/src/provision/cloudflare/setup-world.test-support.ts` (the fake that 59 `cloudflare-setup` unit tests and 43 SETUP criteria tests run on): a Secrets Store `GET` now needs "Secrets Store Read", and any other method still needs "Secrets Store Write". `groupNamed` also searches `EVERYDAY_V2`.
- `packages/framework/src/provision/cloudflare/setup-world.unit.test.ts` — new: "the fake setup world's Secrets Store rules: a GET needs Secrets Store Read, any other method Secrets Store Write". It has two cases: "a token holding only Secrets Store Read … reads the stores and a store's secrets, and writes nothing" (two GETs are 200; POST store, POST secret and PUT secret are 403), and "a token holding only Secrets Store Write also reads the stores (Write implies Read)".
Verdict: accepted
Reasons:
- The cited record is complete and accepted in round 2. Its causal chain holds: 57z added Secrets Store Read and a store-list read to the everyday quick check, while the fake required Write for every Secrets Store request. A real `cloudflare-setup` would report the same 403 correctly. So the fault was in the fake, not in the code under test, and no product test changed its expectation.
- The fix is narrow and method-based, as the round-1 review asked. Writes still need Write, and the new unit test pins both halves: the 403s on POST and PUT stop the fake from becoming permissive. That test is a test of the fake's own rules, so it is new rather than changed, and it is listed here as the plan asks.
- Not verified live: whether Cloudflare lets a token holding only Secrets Store Read list stores. The record and `progress-v0.2.0.md` carry it as a live-pass item, so the fake encodes the plan's assumption (plan §5.2), not an observed fact. That is acceptable for a fake, as long as the live pass checks it.
