# SEC — Secrets

Secret values read by logical name: storage on each target, setting values without exposing them, and the framework's own internal secrets.

Contracts: [secrets.d.ts](../contracts/ts/secrets.d.ts), [errors.d.ts](../contracts/ts/errors.d.ts) (`SEC.*`).

## 1. Requirements

#### SEC-REQ-001 — Declared names only
Origin: owner-approved · Derives from: SYS-REQ-015

App code MUST read only secrets declared in its app definition; other names fail with `SEC.UNDECLARED`. A declared secret with no value in the stage fails with `SEC.MISSING`.

#### SEC-REQ-002 — Values stay secret
Origin: owner-approved · Derives from: SYS-REQ-015

Secret values MUST NOT appear in the repository, configuration files, build output, browser bundles, log entries, or error responses.

#### SEC-REQ-003 — Storage per target
Origin: owner-approved (storage); ai-proposed (locations) · Derives from: SYS-REQ-015

Secret values MUST be stored as follows (DEC-0012):

| Target | Storage | Location of secret `<name>` |
| --- | --- | --- |
| Local | Git-ignored `.dev.vars` file | `SECRET_<NAME>` |
| Cloudflare | Worker secrets | `SECRET_<NAME>` |
| AWS — deferred (branch `aws`) | SSM Parameter Store SecureString | `/<app>/<stage>/secrets/<name>` |

#### SEC-REQ-004 — Setting values
Origin: provenance-unclear · Derives from: SYS-REQ-015

The CLI MUST let the owner set a secret for a target and stage with the value read from standard input, never from command-line arguments or files in the repository.

#### SEC-REQ-005 — Availability
Origin: provenance-unclear · Derives from: SYS-REQ-010

An unreachable secret store MUST surface as `SEC.UNAVAILABLE`. Values MUST NOT be cached across requests. A value MAY be reused within one request.

## 2. Design

**Names.** Logical names are lowerCamelCase in code. `<NAME>` is the upper snake case form (an underscore before each capital: `apiKey` → `API_KEY`); CFG computes the locations with the same function (`config/secret-locations.ts`). The build checks the app's declared names: lowerCamelCase, no duplicates, not starting with `framework`; a violation is `CORE.MISCONFIGURED` listing every problem (DEC-0156).

**Reading values.** The target runtime creates one `SecretsService` per request over a reader of the target's store (local and Cloudflare: the Worker env binding `SECRET_<NAME>`). A name the app did not declare, or any `framework…` name, fails with `SEC.UNDECLARED`; an absent or empty value fails with `SEC.MISSING`. A value found is reused for the rest of that request only; a missing value is not remembered. A store failure becomes `SEC.UNAVAILABLE`, logged once through LOG's `logFailure`; the store's own error text is not carried into the message (DEC-0157). Framework code reads its internal secrets through a separate reader that accepts only the names below.

**Writing values.** `secrets set` and deploy write values with `setSecret` (per-target operations: PROV §2). `secrets set` accepts exactly `<name> --target <t> --stage <s>`; any further positional argument, `--value`, or unknown option is refused, and no error message repeats an argument. The value is standard input, with one trailing line ending removed; empty input is refused. The name must be a declared app secret or a framework-internal secret (DEC-0158).

**Framework-internal secrets** use the reserved prefix `framework`, which app declarations cannot use. They are:
- `frameworkSessionKey`: the session signing key, generated by the CLI per stage when absent (AUTH);
- `frameworkAuthSecret`: the password provider's signing secret (PWD; the credential library's `secret`, which signs verification tokens), 32 random bytes (PAR-253) generated by the CLI per stage when absent, like `frameworkSessionKey`, and stored as the Worker secret `SECRET_FRAMEWORK_AUTH_SECRET` (DEC-0509);
- `frameworkR2AccessKeyId`, `frameworkR2SecretAccessKey`: the R2 signing credentials, created by provisioning (FILES);
- `frameworkLocalTicketKey`: the local file-transfer route's ticket key, local only (FILES; never in a cloud bundle, CORE-REQ-006).

`frameworkGoogleClientSecret`, the Google client secret, is retired with GOOGLE (DEC-0513): it is no longer accepted by `secrets set`, read, or checked, once implementation item I-G lands.

The Data API's database credentials are the one exception to SEC-REQ-003's AWS row. The Data API requires them to be in AWS Secrets Manager, so provisioning creates them there. Neither app code nor SEC reads them (DEC-0061). Deferred (branch `aws`).

**Local.** Missing framework-internal development secrets are generated into `.dev.vars` on first `dev`; existing values are never overwritten. These are `frameworkSessionKey`, `frameworkAuthSecret` and `frameworkLocalTicketKey`, each 32 random bytes (PAR-253) in base64url; an assignment with an empty value counts as missing. `.dev.vars` is written with owner-only permissions. Values are written in the form Wrangler reads back unchanged (its dotenv parse and `$` expansion): `$` is escaped and the value is quoted with the first of `'`, `"`, `` ` `` that reads back exactly; a value with a line break, or one no quoting can represent, is refused. Setting a name replaces its existing assignment in place and keeps other lines (DEC-0159).

**AWS.** `GetParameter` with decryption, using the Lambda role. The role is granted read access to the stage's `/<app>/<stage>/secrets/` path only. Deferred (branch `aws`).

## 3. Uses

CFG (declared names and resolved locations), CLI (setting values), PROV (IAM permissions, Worker secret bindings).

## 4. Acceptance criteria

| ID | Criterion | Verifies | Where |
| --- | --- | --- | --- |
| SEC-AC-001 | A declared secret with a value is returned; an undeclared name fails with `SEC.UNDECLARED`; a declared name without a value fails with `SEC.MISSING`. | SEC-REQ-001 | Local, cloud |
| SEC-AC-002 | A scan of the repository, the build output, the deployed browser assets, the stored log entries, and error responses from a test run finds no test secret value. The stored log entries also contain no test session cookie value and no issued ticket URL; locally, they also contain no stub login provider authorization code, and no test password, verification token or reset token of the password provider. | SEC-REQ-002 | Local, cloud |
| SEC-AC-003 | After a secret is set with the CLI, it exists at the specified location on each target. IAM policy simulation against the stage role shows the AWS Lambda role cannot read another stage's secrets. (IAM simulation clause: deferred, branch `aws`.) | SEC-REQ-003 | Local, cloud |
| SEC-AC-004 | The CLI rejects a secret value supplied as a command-line argument. | SEC-REQ-004 | Local |
| SEC-AC-005 | On each cloud, after `secrets set`, the next request sees the new value; after the test deletes the secret directly through the target's store (a test hook), the next request fails with `SEC.MISSING`. | SEC-REQ-005 | Cloud |

## 5. Portability note

The contract is "read string by name". A new target needs only a store addressable by name and a convention for that name.
